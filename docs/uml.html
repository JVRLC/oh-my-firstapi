Fulki API · schéma du système

Comment le repo est construit

Backend FastAPI pour une app de streaming de khassaïdes (poèmes religieux wolofal/arabes) récités par des kourels : catalogue, auth par OTP, position de lecture, et URLs audio présignées vers AWS S3.

FastAPI SQLAlchemy · async SQLite → PostgreSQL JWT (python-jose) boto3 · S3 presigned URL

01 Modèle de données

Un Kourel interprète des Khassaide (chacun découpé en Verse) ; chaque couple donne un Recording, calé verset par verset via VerseTiming. Côté utilisateur, User accumule progression, favoris et téléchargements.

02 Architecture

Quatre routeurs FastAPI s'appuient sur trois services et une base de données. L'audio ne transite jamais par l'API : signing_service ne fait que générer une URL S3 présignée (6 h), que le client utilise pour streamer directement depuis le bucket.

03 Lire un enregistrement

Séquence complète depuis la demande du client jusqu'au streaming réel de l'audio, en passant par l'incrément du compteur d'écoutes et la génération de la presigned URL. 

sequenceDiagram
    participant C as App cliente
    participant P as player.py
    participant D as Base de données
    participant S as signing_service
    participant B as AWS S3

    C->>P: POST /recordings/{id}/signed-url
    P->>D: SELECT Recording WHERE id AND is_published
    D-->>P: enregistrement trouvé
    P->>D: play_count += 1
    P->>S: signed_url(audio_path)
    S->>S: generate_presigned_url(GetObject, 6h)
    S-->>P: url, expires_in_sec
    P-->>C: 200 { url, expires_in_sec }
    C->>B: GET url
    B-->>C: flux audio
